# Responsive Design y unidades

Hasta ahora hemos trabajado con tamaños como:
```css
.event-card {
    width: 300px;
    padding: 24px;
}
```

Esto funciona bien mientras conozcamos el espacio disponible. Pero Viajia debe funcionar en:
```text
Desktop
┌──────────────────────────────────────────────┐
│                                              │
│                  Viajia                       │
│                                              │
└──────────────────────────────────────────────┘

Tablet
┌────────────────────────────┐
│          Viajia             │
└────────────────────────────┘

Móvil
┌──────────────────┐
│      Viajia      │
└──────────────────┘
```

El navegador necesita poder adaptar nuestro layout.

## 1. px

Ya lo hemos utilizado:
```css
.event-card {
    width: 300px;
    padding: 24px;
}
```

`px` representa una unidad CSS de longitud.

Es útil cuando queremos controlar medidas concretas:
```css
border: 1px solid;
border-radius: 12px;
gap: 24px;
```

De hecho, en el diseño de Stitch que encontraste aparecen valores como:
```text
gutter: 24px
margin-mobile: 16px
container-max: 1280px
```

Por lo tanto, `px` **seguirá siendo bastante habitual en Viajia**.

Pero no debemos construir absolutamente todo utilizando `px`.

## 2. Porcentajes `%`

El porcentaje es relativo al tamaño de algún elemento de referencia, normalmente su contenedor.

Por ejemplo:
```css
.event-card {
    width: 50%;
}
```

Si el contenedor mide:
```text
1000px
```

la tarjeta ocupará aproximadamente:
```text
500px
```

Si el contenedor cambia a:
```text
600px
```

la tarjeta pasa a ocupar:
```
300px
```

Esto es muy diferente de:
```css
width: 500px;
```

que mantiene el ancho fijo en 500px.

### Podemos visualizarlo así
```text
width: 50%

Contenedor 1000px
┌──────────────────────────────────────────┐
│                  ┌───────────┐           │
│                  │   50%     │           │
│                  └───────────┘           │
└──────────────────────────────────────────┘
```

## 3. `rem`

Esta unidad será **muy importante** en proyectos modernos.

`rem` significa:

> root em

Es relativo al tamaño de fuente del elemento raíz (`html`).

Normalmente el navegador utiliza:
```css
html {
    font-size: 16px;
}
```

Por lo que:
```text
1rem = 16px
```

Entonces:
```css
padding: 1rem;
```

equivale normalmente a:
```text
16px
```

Y:
```css
padding: 2rem;
```

equivale normalmente a:
```text
32px
```

Podemos tener:
```css
.title {
    font-size: 2rem;
}
```

y:
```css
.description {
    font-size: 1rem;
}
```

## 4. ¿Por qué usar rem?

Porque permite que nuestros tamaños sean **relativos a una escala tipográfica**.

Imagina que definimos:
```text
1rem = 16px
```

Entonces:
```text
0.75rem = 12px
1rem    = 16px
1.25rem = 20px
1.5rem  = 24px
2rem    = 32px
3rem    = 48px
```

Esto encaja bastante bien con la escala tipográfica que viste en Stitch:
```text
12px
14px
16px
18px
24px
28px
32px
48px
```

En Tailwind posteriormente veremos una escala de tamaños similar.

## 5. `em`

`em` también es una unidad relativa, pero su comportamiento depende del **contexto del elemento**.

Por ejemplo:
```css
.parent {
    font-size: 20px;
}

.child {
    font-size: 2em;
}
```

El hijo tendrá:
```text
2 × 20px = 40px
```

Esto puede producir algo interesante:
```text
html
 ↓
parent
 ↓
child
 ↓
grandchild
```

Los tamaños pueden depender unos de otros.

Por eso, para muchas medidas generales de una aplicación, `rem` suele resultar más predecible.

### Regla inicial para nosotros

No necesitas evitar `em`.

Simplemente recuerda:
```text
rem → relativo al root

em → relativo al contexto tipográfico
```

Más adelante veremos casos donde `em` resulta útil.

## 6. `vw`

Ahora vienen dos unidades muy interesantes para responsive design.
```text
vw = viewport width
```

Es decir:

> porcentaje del ancho visible del navegador.
```css
width: 50vw;
```

significa aproximadamente:

> 50% del ancho del viewport.

Si el viewport mide:
```text
1200px
```

entonces:
```text
50vw ≈ 600px
```

Si mide:
```text
400px
```

entonces:
```text
50vw ≈ 200px
```

## 7. `vh`

Funciona de forma equivalente pero utilizando la altura:
```text
vh = viewport height
```

Por ejemplo:
```css
.hero {
    height: 100vh;
}
```

significa aproximadamente:

> ocupar el 100% de la altura disponible del viewport.

Esto puede utilizarse en pantallas como:
```text
┌──────────────────────────────┐
│                              │
│          Viajia              │
│                              │
│      Explora Oaxaca          │
│                              │
│       [Explorar]             │
│                              │
└──────────────────────────────┘
            ↑
          100vh
```

## 8. Una distinción importante

Tenemos:
```text
%
```

relativo normalmente al **contenedor**.

Mientras:
```text
vw
vh
```

son relativos al **viewport**.

Y:
```text
rem
```

es relativo al **root**.

Esto es algo que quiero que puedas razonar, no memorizar mecánicamente.

## 9. `max-width`

Esta propiedad será especialmente importante para Viajia.

Supongamos que tenemos:
```css
.container {
    width: 100%;
    max-width: 1280px;
}
```

En una pantalla grande:
```text
Monitor 1920px

┌───────────────────────────────────────────────────────────┐
│                                                           │
│       ┌─────────────────────────────────────────┐         │
│       │                                         │         │
│       │             contenido                   │         │
│       │                                         │         │
│       └─────────────────────────────────────────┘         │
│                                                           │
└───────────────────────────────────────────────────────────┘
```

El contenido no seguirá creciendo indefinidamente.

Como máximo tendrá:
```text
1280px
```

Esto coincide directamente con el:
```text
container-max: 1280px
```

que encontraste en el diseño.

## 10. `margin: auto`

Aquí aparece otro patrón extremadamente común:
```css
.container {
    max-width: 1280px;
    margin: 0 auto;
}
```

¿Qué significa?
```css
margin: 0 auto;
```

aproximadamente:
```text
arriba:    0
derecha:   auto
abajo:     0
izquierda: auto
```

El navegador distribuye el espacio horizontal disponible entre ambos márgenes.

Resultado:
```text
┌───────────────────────────────────────────────┐
│                                               │
│       ┌─────────────────────────────┐         │
│       │                             │         │
│       │          contenido          │         │
│       │                             │         │
│       └─────────────────────────────┘         │
│                                               │
└───────────────────────────────────────────────┘
```

Es una técnica fundamental para centrar contenedores.

## 11. Nuestro primer layout responsive

Vamos a construir algo parecido a una sección de Viajia.

### HTML
```html
<section class="events-section">
    <h1>Eventos cercanos</h1>

    <div class="events">
        <article class="event-card">
            <h2>Guelaguetza</h2>
        </article>

        <article class="event-card">
            <h2>Festival de Jazz</h2>
        </article>

        <article class="event-card">
            <h2>Feria del Mezcal</h2>
        </article>
    </div>
</section>
```

### CSS
```css
.events-section {
    width: 100%;
    max-width: 1280px;
    margin: 0 auto;
    padding: 0 16px;
}

.events {
    display: grid;
    grid-template-columns: repeat(3, 1fr);
    gap: 24px;
}

.event-card {
    min-height: 200px;
    border: 1px solid;
    padding: 24px;
}
```

En escritorio tendremos algo parecido a:
```text
┌──────────────────────────────────────────────────────────────┐
│                    Eventos cercanos                          │
│                                                              │
│ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐           │
│ │ Guelaguetza  │ │ Jazz         │ │ Mezcal       │           │
│ └──────────────┘ └──────────────┘ └──────────────┘           │
└──────────────────────────────────────────────────────────────┘
```

## 12. Media Queries

Ahora vamos a decirle al navegador:

> "Cuando la pantalla sea suficientemente pequeña, cambia el layout."
```css
@media (max-width: 768px) {
    .events {
        grid-template-columns: 1fr;
    }
}
```

Ahora:
```text
Desktop

┌──────────┐ ┌──────────┐ ┌──────────┐
│ Evento   │ │ Evento   │ │ Evento   │
└──────────┘ └──────────┘ └──────────┘
```

se convierte en:
```text
Móvil

┌───────────────────┐
│       Evento      │
└───────────────────┘

┌───────────────────┐
│       Evento      │
└───────────────────┘

┌───────────────────┐
│       Evento      │
└───────────────────┘
```

Esto es una **media query**.

## 🧠 Mobile-first

Aquí quiero introducir un concepto que utilizaremos durante Viajia:

> Mobile-first

En lugar de pensar:
```text
Desktop
   ↓
hacerlo más pequeño
   ↓
Mobile
```

pensaremos:
```text
Mobile
   ↓
Tablet
   ↓
Desktop
```

Por ejemplo:
```css
.events {
    display: grid;
    grid-template-columns: 1fr;
    gap: 16px;
}

@media (min-width: 768px) {
    .events {
        grid-template-columns: repeat(2, 1fr);
        gap: 24px;
    }
}

@media (min-width: 1024px) {
    .events {
        grid-template-columns: repeat(3, 1fr);
    }
}
```

Así estamos diciendo:
```text
             MOBILE
                │
              1 columna
                │
                ▼
             TABLET
                │
             2 columnas
                │
                ▼
             DESKTOP
                │
             3 columnas
```

Esto será muy útil porque **Viajia debe funcionar en el navegador tanto en escritorio como en dispositivos móviles**.
