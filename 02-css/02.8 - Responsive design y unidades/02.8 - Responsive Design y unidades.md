# 02.8 Responsive Design y unidades

La idea fundamental es:

> Una interfaz responsive no intenta mantener exactamente el mismo diseño en todos los tamaños; adapta su distribución, dimensiones y comportamiento al espacio disponible.

Por ejemplo, una sección de eventos:

**Móvil**
```text
┌───────────────────┐
│ Eventos cercanos  │
│                   │
│ ┌───────────────┐ │
│ │   Evento 1    │ │
│ └───────────────┘ │
│                   │
│ ┌───────────────┐ │
│ │   Evento 2    │ │
│ └───────────────┘ │
└───────────────────┘
```

**Desktop**
```text
┌─────────────────────────────────────────────┐
│ Eventos cercanos                            │
│                                             │
│ ┌───────────┐ ┌───────────┐ ┌───────────┐   │
│ │ Evento 1  │ │ Evento 2  │ │ Evento 3  │   │
│ └───────────┘ └───────────┘ └───────────┘   │
└─────────────────────────────────────────────┘
```

El contenido puede ser el mismo.

Lo que cambia es el **layout**.
## 1. Unidades
### px

Ya lo hemos utilizado:
```css
.event-card {
    width: 300px;
    padding: 24px;
}
```

`px` representa una unidad CSS de longitud.

Es útil cuando queremos controlar medidas concretas:
```css
border: 1px solid;
border-radius: 12px;
gap: 24px;
```

De hecho, en el diseño de Stitch que encontraste aparecen valores como:
```text
gutter: 24px
margin-mobile: 16px
container-max: 1280px
```

Por lo tanto, `px` **seguirá siendo bastante habitual en Viajia**.

Pero no debemos construir absolutamente todo utilizando `px`.

### Porcentajes `%`

El porcentaje es relativo al tamaño de algún elemento de referencia, normalmente su contenedor.

Por ejemplo:
```css
.event-card {
    width: 50%;
}
```

Si el contenedor mide:
```text
1000px
```

la tarjeta ocupará aproximadamente:
```text
500px
```

Si el contenedor cambia a:
```text
600px
```

la tarjeta pasa a ocupar:
```
300px
```

Esto es muy diferente de:
```css
width: 500px;
```

que mantiene el ancho fijo en 500px.

#### Podemos visualizarlo así
```text
width: 50%

Contenedor 1000px
┌──────────────────────────────────────────┐
│                  ┌───────────┐           │
│                  │   50%     │           │
│                  └───────────┘           │
└──────────────────────────────────────────┘
```

### `rem`

Esta unidad será **muy importante** en proyectos modernos.

`rem` significa:

> root em

Es relativo al tamaño de fuente del elemento raíz (`html`).

Normalmente el navegador utiliza:
```css
html {
    font-size: 16px;
}
```

Por lo que:
```text
1rem = 16px
```

Entonces:
```css
padding: 1rem;
```

equivale normalmente a:
```text
16px
```

Y:
```css
padding: 2rem;
```

equivale normalmente a:
```text
32px
```

Podemos tener:
```css
.title {
    font-size: 2rem;
}
```

y:
```css
.description {
    font-size: 1rem;
}
```

#### ¿Por qué usar rem?

Porque permite que nuestros tamaños sean **relativos a una escala tipográfica**.

Imagina que definimos:
```text
1rem = 16px
```

Entonces:
```text
0.75rem = 12px
1rem    = 16px
1.25rem = 20px
1.5rem  = 24px
2rem    = 32px
3rem    = 48px
```

Esto encaja bastante bien con la escala tipográfica que viste en Stitch:
```text
12px
14px
16px
18px
24px
28px
32px
48px
```

En Tailwind posteriormente veremos una escala de tamaños similar.

### `em`

`em` también es una unidad relativa, pero su comportamiento depende del **contexto del elemento**.

Por ejemplo:
```css
.parent {
    font-size: 20px;
}

.child {
    font-size: 2em;
}
```

El hijo tendrá:
```text
2 × 20px = 40px
```

Esto puede producir algo interesante:
```text
html
 ↓
parent
 ↓
child
 ↓
grandchild
```

Los tamaños pueden depender unos de otros.

Por eso, para muchas medidas generales de una aplicación, `rem` suele resultar más predecible.

#### Regla inicial para nosotros

No necesitas evitar `em`.

Simplemente recuerda:
```text
rem → relativo al root

em → relativo al contexto tipográfico
```

Más adelante veremos casos donde `em` resulta útil.

### `vw`

Ahora vienen dos unidades muy interesantes para responsive design.
```text
vw = viewport width
```

Es decir:

> porcentaje del ancho visible del navegador.
```css
width: 50vw;
```

significa aproximadamente:

> 50% del ancho del viewport.

Si el viewport mide:
```text
1200px
```

entonces:
```text
50vw ≈ 600px
```

Si mide:
```text
400px
```

entonces:
```text
50vw ≈ 200px
```

### `vh`

Funciona de forma equivalente pero utilizando la altura:
```text
vh = viewport height
```

Por ejemplo:
```css
.hero {
    height: 100vh;
}
```

significa aproximadamente:

> ocupar el 100% de la altura disponible del viewport.

Esto puede utilizarse en pantallas como:
```text
┌──────────────────────────────┐
│                              │
│          Viajia              │
│                              │
│      Explora Oaxaca          │
│                              │
│       [Explorar]             │
│                              │
└──────────────────────────────┘
            ↑
          100vh
```

### Una distinción importante

Tenemos:
```text
%
```

relativo normalmente al **contenedor**.

Mientras:
```text
vw
vh
```

son relativos al **viewport**.

Y:
```text
rem
```

es relativo al **root**.

Esto es algo que quiero que puedas razonar, no memorizar mecánicamente.

## 2. `min-width` y `max-width`

Ya los conoces, pero vamos a conectarlos con responsive design.

`min-width`
```css
@media (min-width: 768px) {
}
```

Significa:
```text
768px o MÁS
───────────────►
     aplicar
```

`max-width`
```css
@media (max-width: 767px) {
}
```

Significa:
```text
◄───────────────
hasta 767px
aplicar
```

Cuando trabajamos **mobile-first**, normalmente utilizaremos más `min-width`.

## 3. `margin: auto`

Aquí aparece otro patrón extremadamente común:
```css
.container {
    max-width: 1280px;
    margin: 0 auto;
}
```

¿Qué significa?
```css
margin: 0 auto;
```

aproximadamente:
```text
arriba:    0
derecha:   auto
abajo:     0
izquierda: auto
```

El navegador distribuye el espacio horizontal disponible entre ambos márgenes.

Resultado:
```text
┌───────────────────────────────────────────────┐
│                                               │
│       ┌─────────────────────────────┐         │
│       │                             │         │
│       │          contenido          │         │
│       │                             │         │
│       └─────────────────────────────┘         │
│                                               │
└───────────────────────────────────────────────┘
```

Es una técnica fundamental para centrar contenedores.

## 4. Nuestro primer layout responsive

Vamos a construir algo parecido a una sección de Viajia.

### HTML
```html
<section class="events-section">
    <h1>Eventos cercanos</h1>

    <div class="events">
        <article class="event-card">
            <h2>Guelaguetza</h2>
        </article>

        <article class="event-card">
            <h2>Festival de Jazz</h2>
        </article>

        <article class="event-card">
            <h2>Feria del Mezcal</h2>
        </article>
    </div>
</section>
```

### CSS
```css
.events-section {
    width: 100%;
    max-width: 1280px;
    margin: 0 auto;
    padding: 0 16px;
}

.events {
    display: grid;
    grid-template-columns: repeat(3, 1fr);
    gap: 24px;
}

.event-card {
    min-height: 200px;
    border: 1px solid;
    padding: 24px;
}
```

En escritorio tendremos algo parecido a:
```text
┌──────────────────────────────────────────────────────────────┐
│                    Eventos cercanos                          │
│                                                              │
│ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐           │
│ │ Guelaguetza  │ │ Jazz         │ │ Mezcal       │           │
│ └──────────────┘ └──────────────┘ └──────────────┘           │
└──────────────────────────────────────────────────────────────┘
```

## 5. Media Queries/Breakpoints

Ahora vamos a decirle al navegador:

> "Cuando la pantalla sea suficientemente pequeña, cambia el layout."

```css
@media (max-width: 768px) {
    .events {
        grid-template-columns: 1fr;
    }
}
```

Ahora:
```text
Desktop

┌──────────┐ ┌──────────┐ ┌──────────┐
│ Evento   │ │ Evento   │ │ Evento   │
└──────────┘ └──────────┘ └──────────┘
```

se convierte en:
```text
Móvil

┌───────────────────┐
│       Evento      │
└───────────────────┘

┌───────────────────┐
│       Evento      │
└───────────────────┘

┌───────────────────┐
│       Evento      │
└───────────────────┘
```

Esto es una **media query**.

## 6. Responsive typography

Aquí viene un concepto que todavía no habíamos desarrollado.

Supongamos que tenemos:
```css
h1 {
    font-size: 48px;
}
```

En un monitor grande puede verse perfecto:
```text
┌────────────────────────────────────────────┐
│                                            │
│  Descubre eventos increíbles               │
│                                            │
└────────────────────────────────────────────┘
```

Pero en móvil:
```text
┌──────────────────┐
│ Descubre eventos │
│ increíbles       │
└──────────────────┘
```

El texto puede ocupar demasiadas líneas.

Por eso podemos adaptar la tipografía.

Una forma sencilla:
```css
h1 {
    font-size: 32px;
}

@media (min-width: 1024px) {
    h1 {
        font-size: 48px;
    }
}
```

Pero CSS moderno nos permite algo mucho más interesante.

## 7. 🧠 Mobile-first

> Primero escribimos el CSS para el viewport más pequeño y posteriormente agregamos modificaciones para espacios mayores.

Por ejemplo:
```css
.events {
    display: grid;
    grid-template-columns: 1fr;
}
```

Después:
```css
@media (min-width: 768px) {
    .events {
        grid-template-columns: repeat(2, 1fr);
    }
}
```

Y finalmente:
```css
@media (min-width: 1024px) {
    .events {
        grid-template-columns: repeat(3, 1fr);
    }
}
```

La dirección conceptual es:
```text
Móvil
  ↓
Tablet
  ↓
Desktop
```

No:
```text
Desktop
  ↓
"Vamos a intentar hacer que quepa en móvil"
```

Esto será muy útil porque **Viajia debe funcionar en el navegador tanto en escritorio como en dispositivos móviles**.

## 8. `clamp()`

Esta propiedad la veremos formalmente en la sección de CSS moderno, pero aquí es importante conocer su aplicación.
```css
h1 {
    font-size: clamp(28px, 4vw, 48px);
}
```

`clamp()` recibe:
```text
clamp(
    mínimo,
    valor preferido,
    máximo
)
```

En nuestro ejemplo:
```text
28px
 ↓
mínimo

4vw
 ↓
valor que intenta utilizar

48px
 ↓
máximo
```

Por lo tanto:
```text
Nunca baja de 28px
       │
       ▼
28px ─────────────── 48px
              ▲
              │
       nunca supera 48px
```

Esto permite crear tipografía **fluida**.

En lugar de:
```text
Móvil → 28px
Tablet → 36px
Desktop → 48px
```

podemos permitir que el tamaño cambie progresivamente.

## 9. Responsive images

Ahora llegamos a algo especialmente importante para Viajia.

Tenemos una Event Card:
```html
<article class="event-card">
    <img
        src="guelaguetza.jpg"
        alt="Imagen de la Guelaguetza"
    >
    <h2>Guelaguetza</h2>
</article>
```

Si hacemos simplemente:
```css
img {
    width: 100%;
}
```

la imagen se adapta al ancho.

Pero todavía tenemos un problema:

**¿Qué altura debería tener?**

### El problema de las proporciones

Imagina una imagen:
```text
original

┌──────────────────────────┐
│                          │
│          FOTO            │
│                          │
└──────────────────────────┘
```

Si establecemos:
```css
img {
    width: 100%;
    height: 200px;
}
```

podemos terminar deformándola:
```text
┌────────────────┐
│                │
│     FOTO       │
│                │
│                │
└────────────────┘
```

La imagen original tenía una proporción diferente.

#### `object-fit`

Aquí aparece:
```css
img {
    width: 100%;
    height: 200px;
    object-fit: cover;
}
```

`cover` significa conceptualmente:

> Haz que el contenido cubra completamente el área disponible, aunque sea necesario recortar parte de la imagen.

Por ejemplo:
```text
Imagen original:

┌──────────────────────────┐
│                          │
│          FOTO            │
│                          │
└──────────────────────────┘

          ↓ cover

┌──────────────────┐
│      FOTO        │
│                  │
└──────────────────┘
```

No se deforma.

**Se recorta**.

Esto es extremadamente útil para las imágenes de las tarjetas de Viajia.

#### `object-position`

Podemos controlar qué parte de la imagen queremos conservar.
```css
img {
    object-fit: cover;
    object-position: center;
}
```

También podemos utilizar:
```css
object-position: top;
```

o:
```css
object-position: center top;
```

Esto es útil cuando el elemento importante de la fotografía está arriba.

Por ejemplo, si tenemos una persona:
```text
Imagen:

┌────────────────────┐
│       👤           │ ← importante
│                    │
│                    │
│                    │
└────────────────────┘
```

y el recorte de `cover` elimina la parte superior, podemos utilizar:
```css
object-position: top;
```

#### `aspect-ratio`

Otra propiedad muy importante:
```css
aspect-ratio: 16 / 9;
```

Esto establece una relación de aspecto.

Por ejemplo:
```css
.event-card-image {
    width: 100%;
    aspect-ratio: 16 / 9;
    object-fit: cover;
}
```

Ahora la imagen mantiene aproximadamente:
```text
16
──
9
```

independientemente del ancho.

Así:
```text
Móvil:

┌──────────────────┐
│                  │
│     imagen       │
│                  │
└──────────────────┘


Desktop:

┌──────────────────────────────┐
│                              │
│           imagen             │
│                              │
└──────────────────────────────┘
```

La proporción permanece.

#### Combinando todo

Para una tarjeta de Viajia podríamos terminar con algo como:
```css
.event-card-image {
    width: 100%;
    aspect-ratio: 16 / 9;
    object-fit: cover;
    object-position: center;
}
```

Y esto nos proporciona:
```text
Responsive
    +
proporción constante
    +
sin deformación
    +
recorte controlado
```

Esto es mucho más robusto que establecer arbitrariamente:
```css
width: 300px;
height: 200px;
```
