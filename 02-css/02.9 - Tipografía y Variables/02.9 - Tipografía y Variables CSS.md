# 02.9 - Tipografía

La tipografía no es solamente elegir una fuente. En una interfaz tenemos que controlar varias propiedades:
```text
font-family
font-size
font-weight
line-height
letter-spacing
```

Estas propiedades aparecen directamente en el diseño de Viajia que encontraste.

## 1. font-family

Define la familia tipográfica:
```css
body {
    font-family: "Inter", sans-serif;
}
```

Aquí estamos diciendo:

> Utiliza Inter; si no está disponible, utiliza alguna fuente genérica sans-serif.

En el diseño de Viajia aparecen principalmente:
```text
Montserrat
Inter
```

Por ejemplo, podríamos establecer:
```css
body {
    font-family: "Inter", sans-serif;
}

h1,
h2,
h3 {
    font-family: "Montserrat", sans-serif;
}
```

Visualmente:
```text
Montserrat
━━━━━━━━━━━━━━━━━━
Eventos cercanos

Inter
━━━━━━━━━━━━━━━━━━
Encuentra eventos y experiencias cerca de ti.
```

### ¿De dónde salen las fuentes?

Una página web no puede asumir que el usuario tenga instalada cualquier fuente.

Podemos cargar fuentes externas mediante mecanismos como:
```html
<link ...>
```

o mediante CSS.

Más adelante, cuando lleguemos a la implementación real de Viajia, veremos cuál es la estrategia adecuada.

## 2. `font-size`

Define el tamaño de la letra.
```css
h1 {
    font-size: 32px;
}
```

En el Design System que encontraste tenemos, por ejemplo:
```text
headline-lg       → 32px
headline-md      → 24px
body-lg          → 18px
body-md          → 16px
label-md         → 14px
label-sm         → 12px
display-lg       → 48px
```

Esto es importante porque **no deberíamos inventar tamaños diferentes para cada componente**.

Queremos una escala consistente.

## 3. `font-weight`

Controla el grosor:
```css
h1 {
    font-weight: 700;
}
```

Algunos valores comunes:
```text
400 → normal
500 → medium
600 → semibold
700 → bold
```

En tu configuración aparecen valores como:
```text
headline-lg → 700
headline-md → 600
body-md     → 400
label-md    → 600
```

Por lo tanto, el diseño ya está definiendo una jerarquía.

## 4. line-height

Esta propiedad es especialmente importante.
```css
h1 {
    line-height: 40px;
}
```

No significa el tamaño de la fuente.

Significa aproximadamente **cuánto espacio vertical ocupa cada línea de texto**.

Por ejemplo:
```text
font-size: 32px
line-height: 40px

┌──────────────────────┐
│                      │
│   Eventos cercanos   │
│                      │
└──────────────────────┘
        40px
```

Por eso en tu Design System encontramos:
```text
headline-lg

font-size: 32px
line-height: 40px
font-weight: 700
```

Son **tres propiedades diferentes**.

## 5. letter-spacing

Controla el espacio entre caracteres.
```css
h1 {
    letter-spacing: -0.01em;
}
```

Por ejemplo:
```text
Normal:

E V E N T O S

Más separación:

E  V  E  N  T  O  S
```

o menor separación:
```text
EVENTOS
```

En el diseño aparecen valores como:
```text
-0.01em
-0.02em
0.01em
0.02em
```

Por ahora no necesitas memorizar qué valor utilizar. Lo importante es entender qué controla.

## 6. Crear nuestra escala tipográfica

En lugar de escribir esto constantemente:
```css
.event-title {
    font-size: 32px;
    line-height: 40px;
    font-weight: 700;
}
```

podemos comenzar a crear una especie de **Design System**.

Por ejemplo:
```css
:root {
    --font-headline-lg-size: 32px;
    --font-headline-lg-line-height: 40px;
    --font-headline-lg-weight: 700;
}
```

Y después:
```css
.event-title {
    font-size: var(--font-headline-lg-size);
    line-height: var(--font-headline-lg-line-height);
    font-weight: var(--font-headline-lg-weight);
}
```

Esto introduce un concepto que será fundamental:

# Variables CSS
## 7. Variables CSS

Podemos declarar:
```css
:root {
    --primary: #006e09;
    --background: #faf9f5;
    --surface: #ffffff;
    --on-surface: #1a1c1a;
}
```

Y utilizarlas:
```css
body {
    background-color: var(--background);
    color: var(--on-surface);
}
```

O:
```css
button {
    background-color: var(--primary);
}
```

La sintaxis es:
```css
var(--nombre-de-variable)
```

## 8. ¿Por qué son importantes?

Imagina que Viajia utiliza el verde:
```text
#006e09
```

y tenemos:
```text
Navbar
Botones
Links
Iconos
Eventos
Formularios
```

Si escribimos directamente:
```css
background: #006e09;
```

en veinte lugares, cambiar el color posteriormente sería molesto.

En cambio:
```css
:root {
    --primary: #006e09;
}
```

y:
```css
.button {
    background: var(--primary);
}

.nav-link {
    color: var(--primary);
}

.icon {
    color: var(--primary);
}
```

Ahora basta cambiar:
```css
--primary
```

y todos los elementos se actualizan.

## 9. Y aquí aparece directamente el Design System de Viajia

El código que encontraste en Stitch ya nos estaba dando algo muy interesante:
```text
primary
primary-container
secondary
secondary-container
tertiary
surface
background
error
outline
...
```

Esto **no son simplemente colores aleatorios**.

Es una forma de construir un sistema de diseño mediante **tokens**.

Podríamos representar una pequeña parte en CSS:
```css
:root {
    --primary: #006e09;
    --primary-container: #43c33c;

    --secondary: #006d3d;

    --surface: #faf9f5;
    --surface-container: #eeeeea;

    --background: #faf9f5;

    --error: #ba1a1a;

    --on-primary: #ffffff;
    --on-surface: #1a1c1a;
}
```

Entonces:
```css
body {
    background-color: var(--background);
    color: var(--on-surface);
}

.primary-button {
    background-color: var(--primary);
    color: var(--on-primary);
}
```

Esto empieza a parecerse mucho más a una aplicación profesional.

## 10. ¿Qué significa `on-primary`?

Este detalle es interesante.

En tu configuración aparece:
```text
primary
on-primary
```

No significa simplemente:

> "otro verde."

Conceptualmente:
```text
primary
   ↓
color de fondo

on-primary
   ↓
color del contenido colocado encima
```

Por ejemplo:
```css
.primary-button {
    background-color: var(--primary);
    color: var(--on-primary);
}
```

Visualmente:
```text
┌────────────────────────┐
│       Explorar         │
└────────────────────────┘
 ↑                       ↑
primary              on-primary
```

Esto ayuda a mantener consistencia y contraste.

## 11. surface

También tienes muchos tokens:
```text
surface
surface-container
surface-container-low
surface-container-high
surface-container-highest
```

La idea conceptual es tener diferentes niveles de superficie.

Por ejemplo:
```text
Página
┌─────────────────────────────────────────┐
│ background                              │
│                                         │
│  ┌───────────────────────────────────┐  │
│  │ surface                           │  │
│  │                                   │  │
│  │  ┌─────────────────────────────┐  │  │
│  │  │ surface-container           │  │  │
│  │  └─────────────────────────────┘  │  │
│  └───────────────────────────────────┘  │
└─────────────────────────────────────────┘
```

No necesitas memorizar cada token ahora.

Lo importante es reconocer que **el diseño ya nos está proporcionando una escala de colores/superficies que debemos respetar**.

## 12. Tailwind CSS

Aquí es donde finalmente conectamos con la tecnología que utilizará Viajia.

En CSS tradicional podemos escribir:
```css
.event-title {
    font-family: "Montserrat", sans-serif;
    font-size: 32px;
    line-height: 40px;
    font-weight: 700;
    color: #1a1c1a;
}
```

Con Tailwind podremos expresar esas características directamente mediante clases.

Por ejemplo, conceptualmente:
```html
<h1 class="font-bold text-...">
    Eventos cercanos
</h1>
```

Tailwind nos proporciona clases utilitarias para:
```text
tipografía
espaciado
colores
flexbox
grid
responsive
bordes
sombras
etc.
```

Pero **todavía no quiero que saltemos a Tailwind**.

Primero quiero que tengas una base sólida de CSS.

La razón es importante para tu objetivo profesional:

> Si aprendes Tailwind antes de entender CSS, puedes terminar memorizando clases sin comprender qué está haciendo realmente el navegador.

Como ya tienes experiencia como Android developer, quiero que puedas hacer la equivalencia mental:
```text
Android                    Web

View                       HTML element
Modifier                   CSS / Tailwind
Column                     Flex column
Row                        Flex row
LazyVerticalGrid           CSS Grid
dp                         CSS units
colors.xml                 CSS variables / design tokens
Typography                 CSS typography
Theme                      Design System
```

No son equivalentes técnicamente, pero esta comparación te puede ayudar a construir el modelo mental.
