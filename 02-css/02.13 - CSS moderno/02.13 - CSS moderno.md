# 02.13 - CSS moderno
## 1. CSS Custon Properties.
Ya vimos **CSS Custom Properties**, así que no necesitamos repetirlo desde cero. Lo vamos a usar como base para los siguientes temas.

El orden que te propongo es:
```text
CSS Custom Properties  ✅
        ↓
      calc()
        ↓
      clamp()
        ↓
Container Queries
        ↓
  aspect-ratio
```

Empecemos con `calc()`.

## 2. `calc()`
### 2.1 ¿Qué problema resuelve?

Hasta ahora hemos utilizado valores estáticos:
```css
.container {
    width: 500px;
}
```

o relativos:
```css
.container {
    width: 80%;
}
```

Pero a veces necesitamos **combinar diferentes unidades o hacer cálculos dinámicos**.

Por ejemplo:
```css
.container {
    width: calc(100% - 32px);
}
```

Esto significa:

> Toma el 100% del espacio disponible y réstale 32px.

### 2.2 ¿Por qué no simplemente usar `width: 90%`?

Porque `%` y `px` representan cosas diferentes.

Imagina:
```css
.container {
    width: calc(100% - 32px);
}
```

En una pantalla de:
```text
360px
```

obtendríamos:
```text
360px - 32px = 328px
```

Mientras que en:
```text
1440px
```

obtendríamos:
```text
1440px - 32px = 1408px
```

La ventaja es que el cálculo se realiza **en función del tamaño disponible**.

### 2.3 `calc()` puede combinar unidades

Por ejemplo:
```css
width: calc(100% - 40px);
```

Aquí estamos combinando:
```text
% + px
```

También podemos utilizar:
```css
width: calc(100vw - 80px);
```

o:
```css
font-size: calc(16px + 1vw);
```

CSS se encarga de realizar el cálculo.

### 2.4 Un caso muy útil en Viajia

Recuerda que nuestro Design System tiene:
```text
margin-mobile: 16px
```

Podríamos tener una sección que ocupe todo el ancho disponible menos sus márgenes:
```css
.events {
    width: calc(100% - 32px);
}
```

Conceptualmente:
```text
┌──────────────────────────────────────┐
│←16px→┌────────────────────────┐←16px→│
│      │                        │      │
│      │       Eventos          │      │
│      │                        │      │
│      └────────────────────────┘      │
└──────────────────────────────────────┘
```

Aunque en muchos casos modernos sería preferible conseguir esto mediante `padding` del contenedor, **el concepto de** `calc()` **sigue siendo muy importante**.

### 2.5 `calc()` con Custom Properties

Aquí es donde empieza a ponerse interesante.

Tenemos:
```css
:root {
    --gutter: 24px;
}
```

Podemos hacer:
```css
.container {
    width: calc(100% - var(--gutter) * 2);
}
```

Ahora:
```text
100%
 -
24px
 -
24px
```

El resultado se adapta automáticamente si cambiamos:
```css
--gutter
```

Por ejemplo:
```css
:root {
    --gutter: 40px;
}
```

No necesitamos modificar la regla `.container`.

### 2.6 `calc()` no es solamente para `width`

Puede utilizarse en muchas propiedades:
```css
.element {
    width: calc(...);
    height: calc(...);
    margin: calc(...);
    padding: calc(...);
    top: calc(...);
    font-size: calc(...);
}
```

Por ejemplo:
```css
.header {
    padding-top: calc(16px + 8px);
}
```

Aunque hacer un cálculo tan trivial no tendría mucho sentido, sirve para entender que `calc()` es una **expresión matemática dentro de CSS**.

### 2.7 🧠 Algo importante

No pienses en:

> "`calc()` sirve para restar píxeles".

Piensa en:

> "`calc()` **permite construir valores dinámicos combinando unidades y valores de CSS**."

Ese modelo mental te será mucho más útil.

## 3. `clamp()`
`clamp()` es particularmente interesante porque permite crear **valores fluidos** que tienen un mínimo y un máximo.

Su estructura es:
```css
clamp(min, preferred, max)
```

Es decir:
```text
clamp(
    mínimo,
    valor preferido,
    máximo
)
```

Podemos pensar:

> "Quiero que este valor crezca o disminuya, pero **nunca sea menor que X ni mayor que Y**."

### 3.1 Ejemplo sencillo
```css
.title {
    font-size: clamp(24px, 5vw, 48px);
}
```

Significa aproximadamente:
```text
mínimo     preferido       máximo
  24px        5vw            48px
   │           │               │
   └───────────┼───────────────┘
               ↓
       valor dinámico
```

Cuando cambia el viewport, `5vw` cambia.

Pero `clamp()` impone los límites:
```text
           24px                 48px
             │                    │
             ▼                    ▼
─────────────┬────────────────────┬─────────────
             │     valor fluido   │
             │                    │
          mínimo                máximo
```

### 3.2 ¿Por qué es útil?

Sin `clamp()`, podríamos hacer:
```css
.title {
    font-size: 32px;
}

@media (max-width: 768px) {
    .title {
        font-size: 24px;
    }
}
```

Pero con `clamp()` podemos hacer:
```css
.title {
    font-size: clamp(24px, 3vw, 32px);
}
```

Ahora el tamaño puede **adaptarse progresivamente** al viewport, en lugar de cambiar únicamente cuando cruzamos un breakpoint.

Esto es lo que se suele llamar **tipografía fluida**.

`clamp()` **también funciona con otras propiedades**

No está limitado a `font-size`.

Por ejemplo:
```css
.container {
    padding: clamp(16px, 3vw, 40px);
}
```

O:
```css
.card {
    gap: clamp(12px, 2vw, 24px);
}
```

Incluso podemos combinarlo con nuestras Custom Properties.

## 4. Container Queries
### 4.1 El problema de las Media Queries

Hasta ahora hemos utilizado:
```css
@media (min-width: 768px) {
    ...
}
```

La condición depende del **viewport**:
```text
┌──────────────────────────────────────┐
│              viewport                │
│                                      │
│   ┌──────────────────────────────┐   │
│   │       componente             │   │
│   └──────────────────────────────┘   │
│                                      │
└──────────────────────────────────────┘
             ↑
       mide el viewport
```

Es decir, `@media` pregunta:

> "¿Qué tan grande es la ventana del navegador?"

### 4.2 Container Queries cambian la pregunta

Con Container Queries podemos preguntar:

> "¿Qué tan grande es el contenedor donde está mi componente?"

Por ejemplo:
```text
┌──────────────────────────────────────────────┐
│                Página                        │
│                                              │
│   ┌────────────────────┐  ┌───────────────┐  │
│   │                    │  │               │  │
│   │     EventCard      │  │  EventCard    │  │
│   │                    │  │               │  │
│   └────────────────────┘  └───────────────┘  │
│                                              │
└──────────────────────────────────────────────┘
```

Aunque ambas tarjetas estén dentro de la misma página, una podría tener mucho más espacio disponible que la otra.

Una Media Query mira:
```text
viewport → ¿qué tamaño tiene la pantalla?
```

Una Container Query mira:
```text
container → ¿qué espacio tiene mi componente?
```

### 4.3 ¿Cómo se declara un container?

Primero tenemos que decirle a CSS:

> "Este elemento será un contenedor que podrá ser consultado."

Por ejemplo:
```css
.events-container {
    container-type: inline-size;
}
```

Ahora `.events-container` puede ser utilizado como referencia para una Container Query.

### 4.4 Crear la Container Query

Supongamos:
```css
.events-container {
    container-type: inline-size;
}

.event-card {
    display: block;
}
```

Podemos decir:
```css
@container (min-width: 500px) {
    .event-card {
        display: flex;
    }
}
```

La diferencia fundamental es:
```text
@media
   ↓
viewport

@container
   ↓
container
```

### 4.5 ¿Por qué es interesante para componentes?

Imagina que tenemos un `EventCard` reutilizable.

En una pantalla:
```text
┌─────────────────────────────────────┐
│                                     │
│ EventCard                           │
│                                     │
└─────────────────────────────────────┘
```

Tiene suficiente espacio, así que podemos mostrar:
```text
┌─────────────────────────────────────┐
│ ┌─────────┐  Guelaguetza            │
│ │ Imagen  │  Festival cultural      │
│ └─────────┘                         │
└─────────────────────────────────────┘
```

Pero si el mismo componente aparece en un sidebar:
```text
┌───────────────┐
│ EventCard     │
│               │
└───────────────┘
```

podría cambiar automáticamente:
```text
┌───────────────┐
│   Imagen      │
│               │
│ Guelaguetza   │
│ Festival...   │
└───────────────┘
```

El componente **no necesita saber en qué página está**.

Solamente sabe:

> "Si mi contenedor tiene suficiente espacio, utilizo este diseño."

Esto es especialmente útil cuando construimos sistemas basados en componentes, como haremos con **React**.

### 4.6 Comparación con Media Queries
#### Media Query
```css
@media (min-width: 768px) {
    .event-card {
        ...
    }
}
```

Pregunta:
```text
¿El viewport mide ≥ 768px?
```

#### Container Query
```css
@container (min-width: 500px) {
    .event-card {
        ...
    }
}
```

Pregunta:
```text
¿Mi contenedor mide ≥ 500px?
```

Esta diferencia conceptual es **muy importante**.

### 4.7 No significa que Container Queries sustituyan a Media Queries

No.

Cada una resuelve problemas diferentes.

Podemos tener:
```text
Media Queries
     ↓
estructura general de la aplicación
     ↓
navbar
sidebar
layout principal


Container Queries
     ↓
componentes reutilizables
     ↓
EventCard
UserCard
PostCard
etc.
```

Para Viajia podríamos utilizar ambas.

### 4.6 🧪 Ejercicio — Container Query

Tenemos:
```html
<div class="events-container">

    <article class="event-card">
        <h2>Guelaguetza</h2>
        <p>Festival cultural de Oaxaca.</p>
    </article>

</div>
```

Queremos que:

**Contenedor pequeño**
┌──────────────────┐
│ Guelaguetza      │
│ Festival...      │
└──────────────────┘
**Contenedor ≥ 500px**
┌─────────────────────────────────────┐
│ Guelaguetza    │ Festival cultural  │
└─────────────────────────────────────┘

Intenta construir:

1. El CSS que convierte `.events-container` en un container.
2. Una `@container` que se active a partir de `500px`.
3. Dentro de ella, haz que `.event-card` utilice``display: flex`.

## 5. `aspect-ratio`
Ahora pasamos al último tema de CSS moderno de nuestro roadmap.

Este es **muy relevante para Viajia**.

### 5.1 El problema

Tenemos una tarjeta:
```text
┌───────────────────────┐
│                       │
│       IMAGEN          │
│                       │
└───────────────────────┘
```

Queremos que todas las imágenes tengan siempre la misma proporción aunque las imágenes originales sean diferentes.

Por ejemplo:
```text
Imagen A → 1920 × 1080
Imagen B → 800 × 600
Imagen C → 1200 × 800
```

Si simplemente les ponemos un ancho:
```css
img {
    width: 100%;
}
```

podríamos terminar con alturas diferentes.

### 5.2 `aspect-ratio`

Podemos decir:
```css
.event-card-image {
    aspect-ratio: 16 / 9;
}
```

Esto establece una relación:
```text
ancho : alto

16 : 9
```

Conceptualmente:
```text
┌────────────────────────────┐
│                            │
│          IMAGEN            │ 9
│                            │
└────────────────────────────┘
             16
```

CSS intenta mantener esa proporción.

### 5.3 Combinándolo con `object-fit`

Aquí aparece una combinación que utilizaremos muchísimo:
```css
.event-card-image {
    width: 100%;
    aspect-ratio: 16 / 9;
    object-fit: cover;
}
```

Tenemos:
```text
width
  ↓
ocupa todo el ancho

aspect-ratio
  ↓
mantiene 16:9

object-fit: cover
  ↓
rellena el espacio sin deformar
```

Si la imagen original no tiene exactamente esa proporción, `cover` recorta lo necesario.

### 5.4 Ejemplo en Viajia

Supongamos que Figma establece que las imágenes de nuestras tarjetas tienen una proporción determinada.

Podríamos implementar:
```css
.event-card-image {
    width: 100%;
    aspect-ratio: 16 / 9;
    object-fit: cover;
    border-radius: 12px;
}
```

Entonces todas las tarjetas mantienen una estructura visual consistente:
```text
┌──────────────────────┐
│                      │
│       Imagen         │
│        16:9          │
│                      │
├──────────────────────┤
│ Guelaguetza          │
│ Festival cultural... │
└──────────────────────┘
```

Aunque las imágenes originales tengan dimensiones completamente diferentes.

### 🧠 Diferencia importante

No confundas:
```css
aspect-ratio
```

con:
```css
object-fit
```

`aspect-ratio`

Determina la **proporción del elemento**.
```text
¿Cuánto mide el contenedor?
```

`object-fit`

Determina **cómo encaja el contenido dentro de ese espacio**.
```text
¿Cómo meto la imagen dentro del contenedor?
```

Por eso funcionan tan bien juntos:
```css
img {
    aspect-ratio: 16 / 9;
    object-fit: cover;
}
```

### 🧪 Ejercicio final de CSS moderno

Tenemos:
```html
<article class="event-card">

    <img
        class="event-card-image"
        src="guelaguetza.jpg"
        alt="Guelaguetza"
    >

    <h2>Guelaguetza</h2>

</article>
```

Queremos:

imagen ocupando todo el ancho de la tarjeta;
proporción **16:9**;
que la imagen no se deforme;
que las partes sobrantes se recorten.

Construye tú el CSS utilizando:
```text
width
aspect-ratio
object-fit
```

Y una pregunta conceptual:

**¿Qué diferencia existe entre `aspect-ratio: 16 / 9` y `object-fit: cover`?**
