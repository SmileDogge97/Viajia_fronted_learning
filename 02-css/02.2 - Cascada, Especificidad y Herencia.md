# 02-2 - Cascada, Especificidad, Herencia.
## 1. Especificidad

Podemos simplificarlo inicialmente así:
```text
Selector                  Especificidad aproximada

h2                        1
.event-title              10
.event-card h2            11
```

Entonces:
```css
.event-title
```

tiene una clase → 10

mientras que:
```css
.event-card h2
```

tiene una clase + un elemento → 11

Por eso gana:
```css
.event-card h2 {
    color: blue;
}
```

aunque estuviera escrito antes.

## 2. Cascada

La cascada es el mecanismo mediante el cual CSS determina **qué declaración termina aplicándose cuando existen varias reglas que podrían afectar al mismo elemento**.

La posición de la regla es solamente **uno de los factores**.

Una forma simplificada de pensar en la decisión es:
```text
¿Hay varias reglas aplicables?
          ↓
       Sí
          ↓
¿Hay alguna con mayor prioridad?
          ↓
       Sí → gana
          ↓
Si tienen la misma prioridad:
¿cuál tiene mayor especificidad?
          ↓
Si también empatan:
la que aparece después
```

Más adelante veremos que existen otros factores como:

* origen de la regla;
* `!important`;
* estilos inline;
* capas CSS (`@layer`).

Pero **no quiero que los memorices todavía**.

## 3. 🧠 Una comparación que puede ayudarte viniendo de Android

Piensa en especificidad como una especie de nivel de precisión del selector.

Esto:
```css
h2
```

dice:

> "Quiero modificar los `<h2>`."

Esto:
```css
.event-title
```

dice:

> "Quiero modificar los elementos que tienen `.event-title`."

Y esto:
```css
.event-card h2
```

dice:

> "Quiero modificar específicamente los `<h2>` que están dentro de `.event-card`."

Por eso el último es más específico.

## 4. ⚠️ Pero cuidado con una idea

No quiero que te quedes con:

> "La última regla siempre gana."

Eso **no es correcto**.

Por ejemplo:
```css
.event-card h2 {
    color: blue;
}

.event-title {
    color: green;
}
```

Aunque `.event-title` está después, **seguiría ganando** `.event-card h2`, porque tiene mayor especificidad.

Pero si hacemos:
```css
.event-card h2 {
    color: blue;
}

.event-card h2 {
    color: green;
}
```

ahora sí:

**verde gana**, porque tienen la misma especificidad y la segunda declaración aparece después.

## 5. Un último concepto antes del Box Model: herencia

Hay otra característica de CSS que quiero que conozcas porque aparecerá constantemente.

Supongamos:
```html
<body>
    <main>
        <article class="event-card">
            <h2>Guelaguetza</h2>
            <p>Festival cultural de Oaxaca</p>
        </article>
    </main>
</body>
```

Y tenemos:
```css
body {
    color: green;
}
```

No hemos puesto `color: green` ni en `<h2>` ni en `<p>`.

Sin embargo, normalmente veremos el texto de ambos elementos en verde.

¿Por qué?

Porque algunas propiedades CSS **se heredan de los elementos padres hacia sus descendientes**.

Conceptualmente:
```text
body
 │
 │ color: green
 ↓
main
 │
 ↓
article
 │
 ├── h2
 │
 └── p
 ```

El `color` puede heredarse.

Pero no todas las propiedades se comportan así.

Por ejemplo, si hacemos:
```
body {
    padding: 20px;
}
```

no significa que todos los elementos hijos reciban automáticamente `padding: 20px`.

## 6. 🧠 Una regla mental útil

Puedes pensar:

**Cascada**

> ¿Qué regla gana cuando varias reglas quieren modificar el mismo elemento?

**Especificidad**

> ¿Qué selector es más preciso?

**Herencia**

> Si no establecí una propiedad directamente en este elemento, ¿puede recibirla de su padre?

Son **tres problemas diferentes**.
