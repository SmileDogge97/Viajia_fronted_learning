# 01.5 — DOM y atributos globales

## 1. ¿Qué es el DOM?

DOM significa:

**Document Object Model**

Podemos traducirlo como:

`Modelo de Objetos del Documento`.

Cuando el navegador recibe:
```html
<h1>Eventos cercanos</h1>
```

no se limita a mostrar el texto.

Construye internamente una representación estructurada del documento.

Conceptualmente:
```text
Document
└── html
    ├── head
    └── body
        └── h1
            └── "Eventos cercanos"
```

Esta representación es el **DOM**.

## 2. HTML y DOM no son exactamente lo mismo
Esta distinción es importante.

HTML es el documento que escribimos:
```html
<h1>Eventos cercanos</h1>
```

El navegador lo interpreta y construye un objeto que representa ese elemento dentro del DOM.

JavaScript puede interactuar con esa representación.

Por ejemplo, posteriormente podremos hacer:

```javascript
const title = document.querySelector("h1");
```

y obtener una referencia al elemento.

Después podríamos modificarlo:
```javascript
title.textContent = "Eventos en Oaxaca";
```

El navegador actualizaría lo que vemos.

Por ahora **no necesitas aprender JavaScript todavía**.

Quiero que entiendas solamente esta relación:

```html
HTML
  ↓
Navegador interpreta
  ↓
DOM
  ↓
JavaScript puede interactuar
  ↓
UI actualizada
```
## 3. El DOM es un árbol

Esto debería resultarte familiar.

Si tenemos:
```html
<body>

    <main>

        <section>

            <h1>Viajia</h1>

            <p>Explora Oaxaca</p>

        </section>

    </main>

</body>
```

podemos representarlo:
```text
Document
└── html
    └── body
        └── main
            └── section
                ├── h1
                │   └── "Viajia"
                │
                └── p
                    └── "Explora Oaxaca"
```

Cada elemento tiene una relación con los demás.

Por ejemplo:
```text
section
├── h1
└── p
```

`section` es el padre de `h1` y `p`.

`h1` y `p` son hermanos.

Y `h1` es un hijo de `section`.

Estos conceptos aparecerán constantemente cuando trabajemos con JavaScript y React.

## 4. Una comparación con Android

Aquí puedes utilizar un modelo mental que ya conoces.

Imagina una jerarquía de UI:
```text
Screen
└── Container
    ├── Text
    └── Button
```

En HTML:
```text
body
└── main
    ├── h1
    └── button
```

Ambos forman una estructura jerárquica.

Pero **no quiero que pienses que DOM y el árbol de Views de Android son la misma tecnología**.

La similitud importante es:

`Ambos representan una estructura jerárquica de elementos que permite identificar relaciones entre componentes.`

## 5. id

Ya hemos utilizado:
```html
<input id="city">
```

`id` proporciona un identificador para un elemento.

Por ejemplo:
```html
<h1 id="page-title">
    Eventos cercanos
</h1>
```

Podemos conceptualizarlo como:
```text
h1
└── id = page-title
```

El `id` debe ser **único dentro del documento**.

No deberíamos hacer:
```html
<h1 id="title">Eventos</h1>

<h2 id="title">Lugares</h2>
```

porque tenemos dos elementos con el mismo `id`.

## 6. id y label

Ya utilizamos esta relación:
```html
<label for="city">
    Ciudad
</label>

<select id="city">
    ...
</select>
```

Aquí `id` no solamente sirve para identificar.

También permite establecer una relación semántica entre elementos.
```text
label
for="city"
     │
     ▼
select
id="city"
```

## 7. `class`

Ahora aparece uno de los atributos más importantes de todo frontend:

```html
class
```

Por ejemplo:
```html
<article class="event-card">
    <h3>Guelaguetza</h3>
    <p>Festival cultural...</p>
</article>
```

`class` permite asociar uno o varios elementos con una **clase**.

Por ejemplo:
```html
<article class="event-card">
    ...
</article>

<article class="event-card">
    ...
</article>

<article class="event-card">
    ...
</article>
```

Tenemos:
```text
article → event-card
article → event-card
article → event-card
```

Esto será extremadamente importante en CSS.

Posteriormente podremos escribir:
```css
.event-card {
    ...
}
```

y aplicar estilos a todos los elementos que tengan esa clase.

## 8. `id` vs `class`

Esta distinción quiero que la tengas clara.

`id`

Identifica un elemento específico:
```html
<main id="main-content">
```

Conceptualmente:
```text
main-content → un elemento
```

`class`

Agrupa elementos que comparten una característica:
```html
<article class="event-card">
<article class="event-card">
<article class="event-card">
```

Conceptualmente:
```text
event-card → varios elementos
```

Podemos pensarlo así:
```text
id
 ↓
"¿Quién eres?"

class
 ↓
"¿A qué grupo perteneces?"
```

No es una definición técnica completa, pero es un excelente modelo mental inicial.

## 9. Un elemento puede tener varias clases

Esto:
```html
<article class="event-card featured">
```

significa que el elemento pertenece a dos clases:
```text
event-card
featured
```

CSS posteriormente podrá seleccionar:
```css
.event-card {
    ...
}

.featured {
    ...
}
```

Esto nos permite combinar características.

Por ejemplo, en Viajia:
```html
<article class="event-card featured">
```

podría significar:

`Esta es una tarjeta de evento y además es un evento destacado.`

## 10. data-*

HTML permite crear atributos personalizados que comienzan con:
```text
data-
```

Por ejemplo:
```html
<article
    class="event-card"
    data-event-id="12345"
>
```

Tenemos:
```text
data-event-id = 12345
```

Estos atributos permiten asociar **información personalizada** a elementos HTML.

Por ejemplo, Viajia podría tener:
```html
<article
    class="event-card"
    data-event-id="guelaguetza-2026"
>
```

Posteriormente JavaScript puede leer ese dato.

Esto será útil cuando construyamos interfaces dinámicas.

## 11. title

Otro atributo global:
```html
<button title="Guardar este evento">
    Guardar
</button>
```

`title` proporciona información adicional asociada al elemento.

En muchos navegadores puede aparecer como una pequeña descripción al pasar el cursor.

Pero **no debemos utilizar `title` como sustituto de una interfaz accesible**.

Por ejemplo, no deberíamos hacer:
```html
<button title="Guardar evento">
    💾
</button>
```

y asumir que eso resuelve completamente la accesibilidad.

Más adelante veremos mejores prácticas para botones de iconos.

## 12. hidden

Existe también:
```html
<div hidden>
    Contenido oculto
</div>
```

El navegador no muestra ese elemento visualmente.

Más adelante JavaScript podría modificar ese estado.

Por ejemplo, conceptualmente:
```text
Botón "Mostrar filtros"
        ↓
hidden = false
        ↓
Filtros aparecen
```

Esto será interesante cuando construyamos componentes interactivos.

## 13. Otros atributos globales

Hay muchos atributos que pueden aparecer en diferentes elementos:
```text
id
class
title
hidden
lang
dir
style
tabindex
```

No quiero que los memorices todos ahora.

Lo importante es reconocer que existen **atributos globales**, es decir, atributos que pueden utilizarse en muchos tipos diferentes de elementos.

## 14. `class` será fundamental para CSS

Quiero detenerme aquí porque esto será nuestro puente hacia el siguiente módulo.

Podemos escribir:
```html
<article class="event-card">
    <h3 class="event-title">
        Guelaguetza
    </h3>

    <p class="event-description">
        Festival cultural tradicional de Oaxaca.
    </p>
</article>
```

Todavía no hemos escrito CSS.

Pero ya estamos preparando nuestra estructura para que CSS pueda trabajar sobre ella.

Conceptualmente:
```text
HTML
│
├── estructura
├── semántica
└── clases
        ↓
       CSS
        ↓
   presentación
```

Por eso `class` aparecerá constantemente cuando comencemos a diseñar Viajia.

## 15. Algo que NO quiero que hagas

Cuando empecemos con CSS, podrías descubrir algo como:
```html
<div class="red-big-text">
    Eventos
</div>
```

y luego:
```css
.red-big-text {
    color: red;
    font-size: 40px;
}
```

Funciona.

Pero el nombre:
```text
red-big-text
```

describe **cómo se ve**.

Esto puede convertirse en un problema si mañana el diseño cambia.

Por ejemplo, si el diseñador decide que ahora debe ser azul:

```text
red-big-text
```

ya no tiene sentido.

Es mejor utilizar nombres relacionados con el **rol del elemento**:
```html
<h1 class="event-title">
    Eventos
</h1>
```

y dejar que CSS decida cómo se ve.

Esto será una de las primeras buenas prácticas que aplicaremos cuando lleguemos a CSS.
