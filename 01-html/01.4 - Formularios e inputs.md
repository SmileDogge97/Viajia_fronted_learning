# 01.4 Formularios e inputs

## Formularios

## 1. ¿Qué es un formulario? `form`
Un formulario permite **recibir información del usuario**.

Por ejemplo, en Viajia podríamos tener:
```text
┌─────────────────────────────────┐
│ Buscar eventos                  │
│                                 │
│ ¿Qué buscas?                    │
│ [ conciertos             ]      │
│                                 │
│ Ciudad                          │
│ [ Oaxaca                ▼]      │
│                                 │
│             [ Buscar ]          │
└─────────────────────────────────┘
```

En HTML, el contenedor principal sería:

<form>
    ...
</form>

Por ejemplo:
```html
<form>
    <input type="text">
    <button type="submit">
        Buscar
    </button>
</form>
```

## 2. `input`
`input` representa un campo de entrada.

Por ejemplo:
```html
<input type="text">
```

Esto genera un campo de texto.

El atributo:
```html
type="text"
```

indica qué tipo de entrada esperamos.

Algunos tipos que encontrarás frecuentemente:
```html
<input type="text">
<input type="email">
<input type="password">
<input type="number">
<input type="date">
<input type="search">
<input type="checkbox">
<input type="radio">
```

No necesitas memorizar todos ahora.

La idea importante es:

`input` **es el elemento**; `type` **determina el tipo de entrada**.

## 3. `label`

Este elemento es especialmente importante para accesibilidad.

Tenemos:
```html
<label>
    Ciudad
</label>

<input type="text">
```

Pero todavía no hemos establecido explícitamente que ese `label` corresponde al `input`.

Podemos hacerlo mediante `for` e `id`.

```html
<label for="city">
    Ciudad
</label>

<input
    id="city"
    type="text"
>
```html

Aquí:
```text
label
   │
   └── for="city"
            │
            ↓
        id="city"
            │
            ↓
         input
```

`for` indica qué elemento controla/describe el `label`.

`id` identifica ese elemento.

## 4. ¿Por qué no utilizar solamente `placeholder`?
Podríamos escribir:

```html
<input
    type="text"
    placeholder="Escribe una ciudad"
>
```

Visualmente aparecería algo como:
```text
┌──────────────────────────────┐
│ Escribe una ciudad            │
└──────────────────────────────┘
```

Pero placeholder no sustituye a `label`.

Esto:
```html
<label for="city">Ciudad</label>

<input
    id="city"
    type="text"
    placeholder="Ej. Oaxaca"
>
```

es mejor.

Porque tenemos:
```text
Ciudad       ← nombre del campo
[ Ej. Oaxaca ] ← ayuda/ejemplo
```

Mientras que el placeholder desaparece cuando el usuario comienza a escribir.

## 5. `name`
Ahora aparece un atributo que será muy importante:

```html
<input
    id="city"
    name="city"
    type="text"
>
```

Tenemos:
```text
id   → identifica el elemento dentro del documento
name → identifica el dato del campo
```

Por ahora no necesitas profundizar en la diferencia, pero quiero que empieces a distinguirlos.

Por ejemplo:
```html
<input
    id="event-search"
    name="query"
    type="search"
>
```

Podríamos tener:
```text
id   = event-search
name = query
```

`id` está relacionado con el elemento del DOM y `name` con el dato que representa el campo.

Esto será particularmente importante cuando estudiemos cómo se envían formularios.

## 6. `value`
Podemos establecer un valor inicial:
```html
<input
    type="text"
    value="Oaxaca"
>
```

El campo aparecería inicialmente con:
```text
┌──────────────────────────────┐
│ Oaxaca                       │
└──────────────────────────────┘
```

`value` representa el valor actual/inicial del campo dependiendo del elemento y contexto.

Esto será muy importante posteriormente cuando React empiece a controlar formularios.

## 7. `required`
HTML también permite indicar que un campo es obligatorio:
```html
<input
    type="text"
    required
>
```

Ahora el navegador puede impedir que el formulario sea enviado si el usuario no proporciona un valor.

Por ejemplo:
```html
<label for="email">
    Correo electrónico
</label>

<input
    id="email"
    name="email"
    type="email"
    required
>
```

El navegador ya conoce una regla:

`Este campo debe tener un valor.`

Esto es interesante porque **todavía no hemos escrito JavaScript**.

## 8. Tipos de input y validación nativa
Observa:
```html
<input
    type="email"
    required
>
```

El navegador conoce dos cosas:
```text
type="email"
    ↓
esperamos un correo electrónico

required
    ↓
el campo es obligatorio
```

Esto permite que HTML proporcione cierta validación básica.

No significa que la validación del frontend esté completa.

Posteriormente tendremos que estudiar:

- validación con JavaScript;
- validación en React;
- validación del backend.

Y algo fundamental:

`Nunca debemos confiar únicamente en la validación del frontend para seguridad o integridad de datos.`

El backend debe validar nuevamente los datos.

## 9. `textarea`
`textarea` sirve para introducir **texto de varias líneas**.

Por ejemplo:
```html
<label for="description">
    Descripción
</label>

<textarea
    id="description"
    name="description"
></textarea>
```

Esto sería apropiado para algo como una publicación de Viajia:
```text
Descripción del evento

┌─────────────────────────────────┐
│                                 │
│ Escribe aquí la información...  │
│                                 │
│                                 │
└─────────────────────────────────┘
```

Mientras que:
```html
<input type="text">
```

está pensado normalmente para una sola línea.

## 10. `<select>` y `<option>`
Para seleccionar una opción de una lista:

```html
<label for="category">
    Categoría
</label>

<select id="category" name="category">

    <option value="music">
        Música
    </option>

    <option value="food">
        Gastronomía
    </option>

    <option value="culture">
        Cultura
    </option>

</select>
```

Visualmente podríamos tener:

```text
Categoría

┌──────────────────────┐
│ Música             ▼ │
└──────────────────────┘
```

La parte importante es:

```html
<select>
```

representa el control.

Mientras que:
```html
<option>
```

representa una opción.

## 11. `value` en `<option>`
Observa:
```html
<option value="music">
    Música
</option>
```

Tenemos:
```text
value → music
texto → Música
```

El usuario ve:
```text
Música
```

pero el valor asociado es:
```text
music
```

Esto es bastante común en aplicaciones.

Por ejemplo:
```html
<option value="music">
    Música
</option>

<option value="food">
    Gastronomía
</option>
```

El usuario trabaja con nombres amigables, mientras que nuestra aplicación puede trabajar con identificadores.

## 12. `checkbox`
Para una selección independiente:

```html
<label>
    <input
        type="checkbox"
        name="notifications"
    >

    Recibir notificaciones
</label>
```

Tenemos:
```text
☐ Recibir notificaciones
```

Aquí hemos colocado el `input` dentro del `label`.

Esto también crea una asociación válida entre ambos.

## 13. `radio`
Cuando el usuario debe seleccionar **una opción entre varias**:
```html
<label>
    <input
        type="radio"
        name="transport"
        value="bus"
    >
    Autobús
</label>

<label>
    <input
        type="radio"
        name="transport"
        value="taxi"
    >
    Taxi
</label>

<label>
    <input
        type="radio"
        name="transport"
        value="walking"
    >
    Caminando
</label>
```

Aquí hay un detalle importante:

Todos tienen:
```html
name="transport"
```

Por eso forman parte del mismo grupo.

El usuario puede seleccionar uno:
```text
○ Autobús
● Taxi
○ Caminando
```

## 14. El botón del formulario
Ya conocimos:
```html
<button>
    Guardar evento
</button>
```

Pero dentro de un formulario podemos especificar su tipo:
```html
<button type="submit">
    Buscar
</button>
```

`submit` significa:

`Enviar el formulario`.

También tenemos:
```html
<button type="button">
    Mostrar filtros
</button>
```

Este botón no envía el formulario.

Y:
```html
<button type="reset">
    Limpiar
</button>
```

restablece los valores del formulario a su estado inicial.

## 15. Un formulario completo de Viajia
Ahora podemos juntar lo aprendido:

```html
<form>

    <label for="query">
        ¿Qué buscas?
    </label>

    <input
        id="query"
        name="query"
        type="search"
        placeholder="Ej. conciertos"
    >

    <label for="city">
        Ciudad
    </label>

    <select
        id="city"
        name="city"
    >
        <option value="oaxaca">
            Oaxaca
        </option>

        <option value="cdmx">
            Ciudad de México
        </option>

    </select>

    <label for="date">
        Fecha
    </label>

    <input
        id="date"
        name="date"
        type="date"
    >

    <button type="submit">
        Buscar
    </button>

</form>
```

Esto ya nos permite construir una pequeña interfaz de búsqueda sin **JavaScript**.

## Ejemplo de ejercicio
```html
<!DOCTYPE html>
<html lang="es">
    <head>
        <meta charset="UTF-8">
        <title>Viajia</title>
    </head>
    <body>
        <header></header>
        <main>
            <h1>Buscar eventos</h1>
            <form>
                <label for="event">¿Qué buscas?</label>
                <input id="event" name="event_data" type="search" 
    placeholder="Ingresa lo que quieres buscar" required >
                <label for="city">Ciudad</label>
                <select id="city" name="city_data">
                    <option value="oaxaca">Oaxaca</option>
                    <option value="cdmx">Ciudad de México</option>
                    <option value="puebla">Puebla</option>
                </select>
                <label for="category">Ciudad</label>
                <select id="category" name="category_data">
                    <option value="Music">Música</option>
                    <option value="Gastronomy">Gastronomía</option>
                    <option value="Culture">Cultura</option>
                    <option value="Sports">Deportes</option>
                </select>
                <label for="date">Fecha</label>
                <input id="date" name="date_data" type="date" required>
                <label>
                    <input type="checkbox" name="free_events">
                    Solo eventos gratuitos
                </label>
                <button type="submit">Buscar eventos</button>
            </form>
        </main>
    </body>
</html>
```
