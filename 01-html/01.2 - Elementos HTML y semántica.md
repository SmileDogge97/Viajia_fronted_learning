# 01.2 Elementos HTML y semántica

## 1. ¿Qué es la semántica en HTML?

La semántica tiene que ver con el significado de algo.

Por ejemplo, estos dos elementos podrían verse prácticamente iguales:
```html
<div>Eventos cercanos</div>
```

y:
```html
<h1>Eventos cercanos</h1>
```

Visualmente el navegador los presenta de forma diferente por defecto, pero lo importante es que **no significan lo mismo**.

El segundo está diciendo:

```text
"Este texto es el encabezado principal de esta página."
```

Mientras que el primero solamente dice:

```text
"Aquí hay un contenedor genérico."
```

Esto es HTML semántico.

## 2. Elementos genéricos
### 2.1 `div`

Probablemente uno de los elementos que más vas a utilizar en frontend será:

```html
<div>
    ...
</div>
```

`div` significa básicamente:

```text
"Este es un contenedor genérico."
```

Por ejemplo:
```html
<div>
    <h2>Eventos cercanos</h2>
    <p>Encuentra actividades...</p>
</div>
```

No le estamos diciendo al navegador qué papel semántico cumple ese grupo.

Simplemente agrupamos elementos.

Y eso está perfectamente bien.

El problema sería utilizar `div` **para absolutamente todo**:

```html
<div>
    <div>
        <div>Viajia</div>
        <div>Inicio</div>
        <div>Explorar</div>
    </div>

    <div>
        <div>Eventos</div>
        <div>...</div>
    </div>

    <div>
        <div>...</div>
    </div>
</div>
```

Podría funcionar visualmente.

Pero hemos perdido muchísima información sobre la estructura del documento.

## 3. Elementos semánticos

### 3.1 `header`
`header` representa contenido introductorio o de navegación.

Por ejemplo:

```html
<header>
    <h1>Viajia</h1>
</header>
```

Una página podría tener:

```text
header
 ├── logo
 ├── navegación
 └── acciones del usuario
 ```

En Viajia probablemente tendremos algo parecido a:
```html
<header>
    <a href="/">
        Viajia
    </a>

    <nav>
        ...
    </nav>
</header>
```

### 3.2 `nav`

`nav` representa un conjunto de enlaces de navegación.

Por ejemplo:
```html
<nav>
    <a href="/">Inicio</a>
    <a href="/explore">Explorar</a>
    <a href="/transport">Transporte</a>
    <a href="/profile">Perfil</a>
</nav>
```

Aquí estamos diciendo:
```text
Estos enlaces forman parte de la navegación de la aplicación.
```

No todos los enlaces de una página tienen que estar dentro de `nav`.

Por ejemplo, un enlace dentro de un artículo puede ser simplemente:

```html
<a href="/event/123">
    Ver evento
</a>
```

### 3.3 `main`
`main` representa el **contenido principal de la página**.

Una página normalmente tendrá un elemento `main`.

Por ejemplo:
```html
<body>

    <header>
        ...
    </header>

    <main>
        <h1>Eventos cercanos</h1>

        ...
    </main>

    <footer>
        ...
    </footer>

</body>
```

Una forma sencilla de recordarlo:

```text
body
│
├── header
│
├── main  ← contenido principal
│
└── footer
```

Esto es especialmente importante para accesibilidad.

Por ejemplo, un lector de pantalla puede identificar dónde comienza el contenido principal.
### 3.4 `section`
`section` representa una sección temática del contenido.

Por ejemplo:
```html
<section>
    <h2>Eventos cercanos</h2>

    ...
</section>
```

Otra:
```html
<section>
    <h2>Lugares populares</h2>

    ...
</section>
```

Podríamos tener:
```text
main
│
├── section
│   └── Eventos cercanos
│
├── section
│   └── Lugares populares
│
└── section
    └── Próximos eventos
```

Una regla útil:

```text
Una section normalmente debería representar un bloque temático identificable, y suele tener un encabezado.
```

### 3.5 `article`
`article` representa contenido que puede considerarse **independiente o distribuible por sí mismo**.

Este concepto encaja muchísimo con Viajia.

Por ejemplo, una publicación:
```html
<article>
    <h2>Festival de música en Oaxaca</h2>

    <p>
        Este fin de semana...
    </p>
</article>
```

También podría representar:

- una publicación;
- una noticia;
- una reseña;
- un evento;
- una entrada de blog.

Piensa:
```text
¿Este contenido podría tener sentido por sí mismo fuera de este contexto?
```

Si sí, article puede ser apropiado.

### 3.6 `aside`
`aside` representa contenido relacionado pero secundario respecto al contenido principal.

Por ejemplo:
```html
<main>

    <article>
        ...
    </article>

    <aside>
        Eventos relacionados
    </aside>

</main>
```

En Viajia podríamos utilizarlo para:
```text
┌───────────────────────────────┐
│ Evento                        │
│                               │
│ Información principal         │
│                               │
│                               │
│ Eventos relacionados          │
└───────────────────────────────┘
```

Aunque si algo es simplemente una sección más del contenido principal, quizá section sea más apropiado.

### 3.5 `footer`
Representa el pie de una página o de una sección.

Por ejemplo:
```html
<footer>
    <p>© 2026 Viajia</p>
</footer>
```

Puede contener:

- información de copyright;
- enlaces;
- información de contacto;
- navegación secundaria;
- etc.

### 3.6 Una página semántica

Ahora podemos combinar lo aprendido:
```html
<!DOCTYPE html>
<html lang="es">

<head>
    <meta charset="UTF-8">
    <title>Viajia</title>
</head>

<body>

    <header>

        <a href="/">
            Viajia
        </a>

        <nav>
            <a href="/">Inicio</a>
            <a href="/explore">Explorar</a>
            <a href="/transport">Transporte</a>
        </nav>

    </header>

    <main>

        <section>
            <h1>Descubre qué hacer</h1>

            <p>
                Encuentra eventos, lugares y experiencias cerca de ti.
            </p>
        </section>

        <section>
            <h2>Eventos cercanos</h2>

            <article>
                <h3>Festival de música</h3>
                <p>Oaxaca, Oaxaca</p>
            </article>

            <article>
                <h3>Feria gastronómica</h3>
                <p>Centro histórico</p>
            </article>

        </section>

    </main>

    <footer>
        <p>© 2026 Viajia</p>
    </footer>

</body>

</html>
```

Mira la estructura:
```text
html
│
├── head
│
└── body
    │
    ├── header
    │   ├── logo
    │   └── nav
    │
    ├── main
    │   │
    │   ├── section
    │   │
    │   └── section
    │       ├── article
    │       └── article
    │
    └── footer
```
**Esto ya empieza a parecerse a una aplicación real**.

## 4. ¿Por qué utilizar HTML semántico?
Beneficia a la accesibilidad de los usuarios ya que las tecnologías de asistencia, como los lectores de pantalla, pueden utilizar la información semántica del HTML para comunicar mejor la estructura y propósito del contenido al usuario. Además que proporciona más detalles al navegador respecto al contenido y significado de cada componente en la página web.
